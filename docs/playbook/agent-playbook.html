Parallel Agent Playbook

How we sped up development by running many AI coding agents in parallel, with one agent acting as reviewer, integrator and release manager.

3 agent lanes~10 goals building at once1 spec file per goal0 check-ins before deploy

The loop

  1. Write one spec per goal: what to read first, what to build, and when it counts as done (tests, screenshots, report path, dev-server port).
  2. Launch each goal in its own worktree and branch, so agents never edit the same checkout.
  3. Agents implement, test and write a report with files changed, numbers and screenshots.
  4. The lead reviews the evidence, not the whole diff: report, screenshots, test count. Weak results go back with a short follow-up spec.
  5. Merge, run the full check, deploy, push, one goal at a time as soon as it lands.

Roles

  • Orchestrate, don't implement. One lead agent plans, writes specs, reviews and merges. Implementation goes to cheaper or separate-budget agents.
  • One shared rules file (AGENTS.md) for every agent: git profile, never push or deploy, commit trailer, the check that must pass, translation and performance rules.
  • Measurable bars instead of opinions: a scorecard, a fixed capture rig for before/after shots, and automated audits (HUD overlap, false markers).

Parallel lanes

  • Codex CLI in headless mode, 3–4 sessions at once; more returns HTTP 429.
  • Claude subagents in isolated worktrees, each with its own dev-server port and browser tab.
  • A second Claude Code account run headless with its own config folder (CLAUDE_CONFIG_DIR), so its usage limits add up instead of competing.
  • Split work by subsystem (renderer, clouds, models, effects, AI) so lanes rarely touch the same files.

Keeping the pipeline full

  • A queue runner with a concurrency cap starts the next task the moment a slot frees up.
  • Automatic retry on rate limits: a 429 waits 5 minutes and relaunches instead of failing.
  • Reasoning effort per task: high for big features, medium for merges and small fixes.
  • Background jobs with completion notifications instead of polling.
  • Keep the machine awake (caffeinate) and the session open for overnight runs.

Merging fast

  • Merge early and often: each goal as it lands, not in a batch at the end.
  • Script the recurring conflicts: we had two hotspots (a registry list and a generated manifest) and resolved both with small union scripts.
  • Hand hard conflicts to an agent on a dedicated merge branch, with both feature specs as context, while the lead reviews the next goal.
  • Hold dependent goals until their foundation is merged, or tell them to use only merged APIs.

Autonomy

  • Standing permission to merge, deploy and push once checks pass, with no "ready to ship?" questions.
  • No planning questionnaires: the lead picks goals from the owner's stated focus and starts; the owner redirects if needed.
  • Short status messages after each landing: what shipped, what is building, what is blocked.

Pitfalls we hit

  • Headless agent CLIs can hang waiting on stdin. Always redirect < /dev/null.
  • Editing a runner script while runs are reading it breaks those runs.
  • macOS ships bash 3.2: an empty array under set -u crashes. Use ${A[@]+"${A[@]}"}.
  • Counting sessions with pgrep -f also matches your own waiting loop. Match the binary path.
  • Too many parallel sessions on one account triggers rate limits. Cap it, or add accounts.
  • Machine sleep or a closed session kills long background jobs. Make them resumable.
Tools used: Claude Code (lead and subagents), OpenAI Codex CLI, git worktrees, Vite, Vitest, Cloudflare Workers.
