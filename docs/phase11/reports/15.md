# Phase 11 · 15 — Touch and phone gunner: report

Branch `phase11/15-touch-gunner` (Claude cloud lane; no GPU, Blender or voice tools on this machine).

## What already worked (before this goal)
Touch drag aim, FIRE (hold, slide to aim) / ZOOM / LOOK, tappable gun-position bar, the rotate-your-phone
overlay, a PWA manifest and service worker, and a graphics auto-pick that caps phones at Medium.

## What changed
| Area | Change |
|---|---|
| **Gyro aim** | New `src/core/Gyro.ts`: `devicemotion` rotation rate → mouse deltas, 1:1 (a degree of phone is a degree of gun), screen-angle aware (both landscapes), with a tremor dead zone and a ceiling for violent motion. It works alongside drag aim. A **GYRO** button on the touch HUD (gunner) and Settings → Touch & gamepad → *Gyro aim* / *Gyro sensitivity*. On iOS it asks for motion permission from the tap (click). The listener only runs while gyro aim is on, and it allocates nothing per frame. |
| **Station switching** | **◀ ▶** buttons above FIRE cycle the gun positions (the same `cycleSeat` the gamepad LB/RB use, now one method in `DeviceControls`). On a phone the clean HUD hides the seat bar, so before this there was no visible way to change seats. They keep their LTR order in Arabic. |
| **Reload** | **RELOAD** hold button (holds R: a tap reloads, holding clears a jam). Before this, touch players had no way to reload by hand. |
| **Phone HUD** | Phone-sized touch targets are now 44 px or bigger. The left HUD corners clear a landscape notch (`safe-area-inset-left`). On touch phones the seat-bar labels are at least 11 px and the objective and kill-feed text is bigger. |
| **Mobile performance** | New `src/render/PhonePerf.ts`: *Phone performance mode* (Automatic = phones / Always on / Off). It caps the render pixel budget (0.75 Mpx, or 0.5 Mpx on ≤4 GB / ≤4-core phones) and scales the visual particle budget, on top of the chosen preset. Dynamic resolution still runs under it. Hook: `Engine.phone` + `Engine.setPhoneProfile()` (budget in `resize()`, particles in `setQuality()`). |
| **PWA install flow** | New `src/core/Install.ts` (rules) + `src/ui/InstallPrompt.ts` (card). After the first sortie, on the title screen, on touch devices: Android/Chrome gets an **Install** button that opens the browser's own dialog (`beforeinstallprompt`), and iPhone/iPad Safari gets "Tap Share, then Add to Home Screen". It never shows in the installed app. *Not now* snoozes it for 3 days, and it stops asking after 3 refusals. It hides as soon as a mission starts and never covers the first-run onboarding prompt. |
| **Arabic** | New table `src/i18n/ar/touchGunner.ts` (registered in `src/i18n/phrases.ts`) covers every new string. |

## Not done / limits
- No real phone was available: gyro signs come from the W3C axis definitions and unit tests, not from
  holding a device. Someone should check them once on an Android phone and an iPhone (both landscapes).
- No GPU here, so the phone performance mode's frame-time gain was not measured. The cap is
  conservative (about DPR 1.4 on a 6.1" phone).
- I did not run the Phase 10 capture rig (`tools/visual_rig.mjs`) because this goal is UI only. The shots above use the same
  phone viewport before and after instead.
- No new radio lines, so no voice generation was needed.
