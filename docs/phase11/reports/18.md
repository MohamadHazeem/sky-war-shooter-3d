# Phase 11 · 18 — Co-op lobbies and quick join: report

Branch `phase11/18-coop-lobbies` · lane: Claude cloud session (code only: no Blender, voice tools or GPU on this machine).

## What changed

**Public lobby browser and quick join (B-17 crew mode).** The host can tick "List it publicly — anyone can join"
(on by default, remembered; hidden for the P-51 pilot mode). A public game publishes a small listing
`coop_lobbies/{CODE}` (callsign, crew 1–4, open seats, lobby or battle + wave, coarse region). The host
updates it when the crew, phase or wave changes (at most once every 5 s), sends a heartbeat every minute
and deletes it on leave. The co-op menu has two new buttons:
- **Find a game** lists open crews. Each row shows the callsign, crew count, region, lobby or battle
  (with the wave) and latency bars. A row's Join button joins that crew.
- **Quick join** tries the three best candidates in order and falls through when one is full or gone.

Ranking order: latency band, then crews waiting in the lobby, then fuller crews, then the freshest listing.
Full, stale (older than 3 min), future-dated and own games are hidden.

**Region / latency hints.** The region comes from the IANA time zone (`Intl`; no location lookup). There are
8 regions, including Middle East. The browser estimates each crew's round trip from a region-to-region
table and shows it on the same 4-bar scale as the in-game connection indicator. The tooltip gives the
estimate in ms.

**Friend invite links.** Both host and guest lobbies have "Copy invite link" (the share sheet on touch
devices, the clipboard elsewhere). It links to `…/?join=CODE`. Opening such a link joins that code once the
title screen is up, and the parameter is removed from the address bar so a reload does not join again.

**Rejoin after disconnect.** A guest keeps a 15-minute ticket in localStorage.
- **Dropped connection mid-round:** "Connection lost — rejoining…" appears and the guest retries the same
  code 4 times, 4 s apart. The host already re-offers a departed slot. Back aboard, the host's `start` for
  the same run is accepted once, and the round reloads around the guest.
- **After a reload or a crash:** the co-op menu shows "Rejoin your last crew CODE".
- **Ticket cleared:** when the player leaves deliberately (Leave / Leave co-op) or the host closes the lobby.

**Host migration (fallback: graceful end).**
- **The plan:** every crew `lobby` and `start` message carries a plan `{ heir, next, pub }`. The heir is
  the lowest connected crew id. `next` is a fresh room code, chosen once per hosting.
- **Host leaves on purpose:** if the host leaves mid-round (quit to title, Leave co-op), it sends `migrate`
  before `bye`.
- **Host vanishes:** the guests first try to reconnect (see above). If that fails, they act on the last plan.
- **Heir:** its puppet world becomes the real battle and the director picks up at the synced wave.
  - The proxies are ordinary `spawnEnemy` / `Bomber` aircraft, so restoring `World.update` lets them fly
    and fight.
  - It installs the host wrappers, opens three crew rooms under `next` and relists the game if it was
    public. Message: "The host left — you now run the battle".
  - The crew score carries over. Personal ledgers restart for the remaining part of the round.
- **Other guests:** they get a graceful-end debrief of the sortie so far (personal rewards from the last
  streamed scores). "Return to co-op lobby" rejoins the heir's code, with up to 8 tries 4 s apart, straight
  into the running battle (the existing late-join path).
- **Graceful end:** with no plan (old host build, the pilot mode, a lost heir), every guest gets that
  debrief instead of being dropped to the title.

**Firestore rules** (`firestore.rules`, merged, **NOT deployed**). The new `match /coop_lobbies/{code}`:
- Fixed shape and types: crew + open = 4, phase and region enums, name 1–20 characters,
  `updatedAt == request.time`, `expiresAt` 90–150 min ahead (ready for a TTL policy).
- Create: only the owner of that code's slot-0 signalling room (`coop_rooms/{code}.host`).
- Update: only by the host, at most every 3 s.
- Delete: only by the host.
- Reads: signed-in players only; `list` is limited to 20 per query.
- No other rule changed.

Deploy with `npx firebase-tools deploy --only firestore:rules --project sky-war-shooter-3d`. The browser
query is a single-field range plus `orderBy` on `updatedAt`, so no composite index is needed. Until the
rules are deployed, publishing fails quietly (console warning only) and the browser shows the "Could not
load the game list" message. Codes, invite links and rejoin still work.

## Not done / caveats
- **Firestore rules not deployed** (as instructed). They need a deploy before the browser and quick join
  work live.
- **No live multi-player test.** No second machine and no Firestore/WebRTC from this sandbox. Migration and
  rejoin are covered by unit tests of the session flow with stubbed links. A real 3–4 player playtest of
  host leave / host crash is needed, especially heir takeover:
  - the round director restarts its pacing state at the synced wave;
  - personal scores before the migration stay in the departed host's ledger.
- **Rejoining guests restart their personal ledger** for the rest of the round. Their earlier hits stay in
  the host's `departed` record, so crew totals are right.
- **No mid-round migration in the P-51 pilot mode** (its rooms close after connecting): guests get the
  graceful-end debrief.
- **Region is approximate** (time zone based) and the latency is an estimate. The real RTT bars appear once
  connected.
- **No Blender, voice or GPU steps needed.** The capture rig (`tools/visual_rig.mjs`) was not run: this goal
  is UI/network only. UI shots above.
