# Phase 11 · 27 — Mission editor and sharing: report

Branch `phase11/27-mission-editor`. Players build a B-17 gunner mission, share it as a short code or link,
and fly, rate and replay missions other players send them.

## What players get
- **Mission Editor** tab on the Survival screen (More modes → Mode: Mission Editor). It has **Build a mission**,
  a field to paste a code or link, and **Your missions**: built and shared missions with star ratings, plays and
  best score, and Fly / Edit / Copy link / ✕ on each.
- **Editor** (`#me-screen`): optional name and a target (10 targets). Three collapsible groups, following
  the Phase 8 layout:
  *Enemy waves* (enemy skill; up to 8 waves, each with a leg (way in / over the target / way home), a direction,
  1–12 fighters and any mix of the 10 enemy types), *Route & sky* (short/medium/long route, time of day, 9
  weathers), *Bomber, escorts & flak* (seat, formation of 6–18, flak density none/light/heavy/deadly, escort
  none/from the start/after the target). A live summary, the share link with **Copy link**, and Defaults / Save /
  **Fly mission**. The draft is kept between visits.
- **Share link** `…/?mission=CODE` (also `#mission=`). On load the title screen opens a **shared-mission card**
  with the summary, the waves per leg, your rating, and Edit a copy / Save / **Fly mission**. The parameter is
  removed from the URL so a reload doesn't open it again. A shared link goes before a new player's first-flight
  prompt. A damaged or foreign code shows a clear message.
- **Debrief** of a player mission: a "Rate this mission" strip (1–5 stars), "Flown N times · best S" and
  Copy link. Replaying uses the debrief's existing Retry, or Fly in the library.
- Full Arabic and RTL; works at phone size (390×844) with no horizontal scroll.

## How it works
- `src/game/MissionEditor.ts` (new, pure): the `MissionSpec` model, `sanitizeSpec`, and the share-code codec.
  The code packs every field into a fixed bit layout: version 4 bits, indices and ranges in a few bits each,
  19 bits per wave, then the name as UTF-8 and a 16-bit checksum. It is base64url text: the default mission is
  25 characters, and the largest possible one fits in `CODE_MAX` = 160. The module also has `buildUserMission`
  (spec → an ordinary wave `Mission`), link helpers, and the local library (`sws3d.missionEditor.v1`:
  plays, wins, best, rating, capped at 40) plus the draft.
- **Validated and sandboxed**: `decodeMission` treats a code as untrusted input. It rejects a wrong version, a
  bad checksum (every single-character typo is caught), any index or range outside the fixed lists, trailing
  bytes, oversized codes and invalid UTF-8. It never clamps a bad code into a mission. The name is the only free
  text: `cleanName` normalises it to NFC, keeps only letters, digits, spaces and `- . , ! ? # ( ) :` (no
  HTML-special, control or bidi-override characters), caps it at 24 characters, and it is escaped again
  wherever it is shown. Library entries from storage are decoded again on load, so tampered entries are
  dropped. All player missions share one id (`user-mission`): codes cannot create progress keys or touch
  campaign unlocks. The registered mode's board is `''`, so player missions never post to the online
  leaderboards.
- Mission build: waves are ordered by leg. The first group of each leg is timed (way in at 8 s, over the
  target 45 s before bombs away, way home 30 s after). Later groups in a leg come once the sky is clear (the
  existing `afterClear` logic). Bombs away is at 55 % of the route, with the flak window around it; escorts
  arrive at 20 s or 15 s after bombs away. Enemy skill climbs across the waves within the chosen skill's range,
  and the loss limit is 40 % of the formation.
