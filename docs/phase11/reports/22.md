# Phase 11 · 22 — Nightly QA in CI (report)

Branch `phase11/22-nightly-qa`. Code-only goal; done in a cloud session (no GPU, Blender or voice tools, none needed).

## What changed
- **`.github/workflows/nightly-qa.yml`** (new). Runs at 02:17 UTC every night. It can also be started by hand
  (`workflow_dispatch`, with the `set` and `diffs` inputs). The sweep is split over a 10-runner matrix. Each runner caches
  `node_modules` (same key as `ci.yml`). It installs Playwright 1.56.1 outside the project (`~/pw`, cached, not a game
  dependency) and `--only-shell chromium`. Then it starts the Vite dev server (`sws.qa` exists only in dev builds) and runs
  `tools/qa_sweep.mjs nightly` with `QA_SHARD=i/10` and `QA_SWIFTSHADER=1`. Each shard uploads its JSON lines. The
  `summary` job always runs. It merges the shards, writes the job summary, uploads the `nightly-qa-summary` artifact
  (summary.md, findings.json, every JSON line) and opens an issue labelled `nightly-qa`. If an issue is already open, it
  comments there instead, listing only findings not reported yet. A push that edits the workflow runs the one-mission
  smoke set as a self-test that must be clean, and opens no issue.
- **`tools/nightly_qa.mjs`** (new, pure Node, no dependencies):
  - `classify`: the findings of one run, with stable keys (numbers, hashes and query strings are stripped)
  - `summarize`: Markdown summary; a shard that did not finish is itself a finding
  - `shardJobs` / `parseShard`: split the job list across runners
  - `reportedKeys` / `issueBody`: deduplicate against the open issue through a hidden `<!-- nightly-qa-keys: [...] -->` line
  - Command-line use: `summary …` and `issue …`
  - Types are in `tools/nightly_qa.d.mts`.
- **Findings** (a nightly run must never show these, at any bot skill):
  - page errors
  - crashes
  - softlocks: the mission never ended within the step cap, the world clock was frozen ≥ 5 s while playing, or a job
    hung the page
  - HUD panel overlaps
  - false markers
  - a B-17 loss counted twice

  Not findings: losing a mission (the human-level bot loses some) and frame times (SwiftShader says nothing about the real
  GPU budget).
- **`tools/qa_sweep.mjs`** (hook lines):
  - New `nightly` set: every gunner campaign mission incl. Deep Penetration × `QA_DIFFS` (recruit, veteran, ace), gunner
    Survival to round 6, and m1 at High quality in Arabic. That makes 50 jobs.
  - `QA_SHARD`.
  - `QA_SWIFTSHADER` (`--use-angle=swiftshader --enable-unsafe-swiftshader`).
  - `QA_JOB_TIMEOUT_S` (default 1500). A job that hangs the page is recorded as `job timeout … (softlock?)`, the page is
    closed and the next job gets a fresh one. Before this, one hang stalled the whole sweep.
- **`tests/nightlyQa.test.ts`** (new, 10 tests) and **`docs/TESTING.md`** (new "Nightly QA in CI" section).

## Verification
- `npx tsc --noEmit` passes. `npx vitest run tests/nightlyQa.test.ts tests/qaSweep.test.ts`: 20/20 pass.
- Local runs in this container (no GPU, Playwright headless shell + SwiftShader, dev server):
  - smoke m1 Veteran: win, 0 findings, 225 s wall
  - `QA_SHARD=2/25` of `nightly` (m2 Recruit, dp4 Veteran): both won, 0 HUD overlaps, 0 false markers, 0 errors, about
    230 s each
  - Hang guard with `QA_JOB_TIMEOUT_S=30`: both jobs were recorded as softlocks and the second ran on a fresh page. The
    issue body was produced correctly (2 findings plus the keys line).
- **Timing:** about 4 min per mission under SwiftShader (each sampled frame renders in about 1.6 s), so a shard of 5 jobs
  takes about 20–25 min. The 10 shards run in parallel; Actions minutes are free for a public repo.
- GitHub: `CI` is green on the branch. The `Nightly QA` push self-test passed all 10 shards (shard 1 ran m1 in about
  3 min on a GitHub runner) and its summary job passed too.
