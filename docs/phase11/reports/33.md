# Phase 11 · 33 — Co-op crew intercom (voice): report

Branch `phase11/33-crew-intercom`. Push-to-talk voice between co-op crew members over the existing WebRTC
links (Opus), with an interphone filter, per-player mute and volume, and an indicator of who is talking.
Text pings (`U`) still work.

## How it works
- **Transport (`src/net/Intercom.ts`)**: every co-op link gets 4 audio transceivers, negotiated in the initial
  offer. No extra connections and no renegotiation. Talking only swaps tracks in and out with `RTCRtpSender.replaceTrack`.
  The host is the hub of the crew's star topology:
  - slot 0 carries voice both ways (guest ↔ host);
  - slot j > 0 carries host → guest: crew member j's voice, relayed (the host forwards the received track unchanged).

  The guest flips its slot‑0 transceiver to `sendrecv` in the `track` event while the offer is applied, so
  `Signal.ts` needed no changes. Opus is WebRTC's default codec, and each sender is capped at 32 kbps. Nothing is sent
  while nobody holds the key, because senders then have no track. Talk state goes on the reliable events channel as
  `{t:'talk', on, from}`. The host re-stamps `from` with the link's crew id and relays it to the others.

  Once a second, `tick()` does three things: it drops talkers whose link closed, it re-applies the routes, and it
  tells any link that opened or reconnected mid-call who is talking. The live check found this last case: a guest
  that reconnected during mission load never saw the host's "talk on".
- **Playback (`src/audio/RadioVoice.ts`)**: each speaker's track goes through an interphone filter into the
  crew‑voice bus. The chain is high‑pass 320 Hz → +5 dB presence peak at 1.7 kHz → low‑pass 3 kHz → tanh
  overdrive → low‑pass. It adds a synthesised key‑on click with a short static burst and a key‑off click. Gain follows
  talk state × mute × volume, with a 0.25 s release so the last syllable isn't cut. It works around Chrome's
  remote‑track quirk with a muted `<audio>` element.
- **Glue (`src/game/CrewIntercom.ts`)**:
  - Push-to-talk uses the remappable **Talk** action (new KeyMap action `talk`, default **Y**, both roles) or the
    hold buttons.
  - The microphone is requested the first time you talk (echo cancellation, noise suppression and AGC on). It is
    stopped when the session ends. If the mic is blocked, a toast says "text pings still work".
  - Mute and volume are saved per callsign in `sws3d.intercom.v1`; the 40 most recently changed callsigns are kept.
- **UI (`src/ui/IntercomHud.ts`)**, kept simple:
  - **Lobby:** a "Crew intercom" panel with a hold‑to‑talk button, the mic state, one row per crewman (talking dot,
    volume slider, Mute) and an intercom volume slider.
  - **Mission:** a "Hold to talk (Y)" button above "Ping target", which moves to the free left‑middle edge on short
    phone‑landscape screens, plus a strip under the connection bars naming who is talking. "You" appears while you
    transmit, and muted crewmen are shown struck through.
- **Arabic**: `src/i18n/ar/intercom.ts` (all new strings, including the KeyMap label).

## Tests
- `tests/intercom.test.ts` (17 tests), using fake transceivers:
  - routing (host relay, guests never relay, a departed crewman is not routed) and speaker→slot mapping;
  - transceiver setup (4 on the host, only the guest's slot 0 flipped, no crash without WebRTC audio);
  - guest push‑to‑talk on slot 0 only, the bitrate cap, and no transmission without a mic;
  - host relay that never echoes to the speaker, plus de‑duplication;

## Live verification (`tools/intercom_check.mjs`, port 5333)
Three tabs in Playwright's bundled headless shell, with Chromium's fake microphone:
- host Reed and guest Walsh at 1200×800;
- guest أحمد in Arabic at phone landscape 844×390, with touch.

They used real Firestore signalling and real WebRTC. Results are in [verification.json](../shots/33/verification.json):
- **SDP**: 4 `m=audio` per link, Opus 48 kHz, slot 0 `sendrecv`, relay slots `sendonly`.
- **Lobby, Walsh holds the button**:
  - the host received 9.8 KB on Walsh's slot 0;
  - أحمد received the **relayed** voice: 10.6 KB on slot 1, and 0 B on the empty slot;
  - the crew‑voice bus peaked at about 1.0 after the radio filter on both listeners (idle: 0).
- **Mute**: muting Walsh on أحمد's side brought the bus to 0 while he kept talking.
- **Leaving**: Walsh left, his mic was released (`mic: 'off'`, stream `null`), and the host's roster dropped to 2.
- **Mission**:
  - the host held **Y** while أحمد held the **touch** hold button, so both talked at once;
  - each heard the other: 6.9 KB and 3.6 KB inbound, with bus peaks of about 1.0;
  - the indicators read `["أنت","Reed"]` on the guest and `["You","أحمد"]` on the host, and cleared on release;
  - no page errors.

## Notes / not done
- On this heavily loaded machine (three game tabs plus other agents' jobs), guests sometimes timed out and
  reconnected during mission load. This is the existing co-op link timeout, not this goal. It is why the check runs
  the mission part with two tabs, and why the mid-call catch-up was added.
- No gamepad binding for talk; keyboard, mouse and touch only. Voice is peer to peer with the host as relay, so a
  host on a weak uplink carries up to 3 × 32 kbps of relayed voice.
- Running the check needs Playwright; locally I used `PLAYWRIGHT_MODULE=… HEADLESS_SHELL=…` to reuse the installed
  headless shell (`executablePath` override, still the bundled shell, never `channel: 'chrome'`).
