# Phase 11 · 36 — Save system 2.0 (report)

Branch `phase11/36-save-system`. Implemented by Claude.

## What changed
- **Versioned schema with migrations** (`src/game/SaveSystem.ts`). The profile (every `sws3d.*` key) now carries
  `sws3d.save.meta` = `{schema, savedAt, hash}`. `SAVE_SCHEMA = 2`; `MIGRATIONS[n]` moves a profile from n to n+1.
  A profile without meta counts as schema 1. Step 1→2 drops device-only keys (cloud code, co-op ticket, dev
  analytics flag) from carried profiles and runs the campaign-layout migration (`migrateProgress`). At boot the stored
  profile is backed up ("Before an update") and migrated before the game reads any store. Files and cloud copies are
  migrated on import too; a file from a newer schema is refused with a clear message.
- **Automatic local backups.** One at every game start and one ~2.5 s after every mission (the existing mission-end
  `pushSave` call schedules it, so it also works offline), plus "Save now" in Settings. Copies identical to the newest
  one are skipped, and a damaged profile is never backed up, so a broken state cannot push out good copies.
  Rotation keeps the 4 newest plus the newest copy older than a day and the newest older than a week. If storage is full,
  the oldest copies are dropped until the new one fits. Backups live under `swsbak.*` (outside the `sws3d.` prefix, so
  they never go to the cloud). A separate **undo slot** holds the profile as it was before the last restore, import, repair
  or cloud merge.
- **Export / import of the whole profile.** A JSON file `sky-war-profile-YYYY-MM-DD.json`
  (`{format: 'sws3d-profile', schema, savedAt, hash, keys}`). Import also accepts the bare key map of a pre-2.0 cloud copy.
- **Cloud sync conflict resolution** (`src/net/CloudSave.ts`). A push first reads the cloud copy. If another device
  changed it since this device last synced, `resolveConflict` runs: **newest wins** (the newer profile is taken whole:
  settings, loadout, campaign state), then the growing stat stores of the older side are **merged in**:
  progress, career, achievements, mastery, feats and museum. Numbers keep the max (`enlisted` keeps the min), lists of
  plain values are joined, and objects merge per field. A damaged store never overwrites a good one. Armory points
  (a spendable currency) are deliberately not merged. "Load profile" by code takes that profile as the base and merges
  this device's stats in. After a merge the device keeps merging on every push until a restart, so older in-memory stats
  written back by the running game cannot lower the cloud copy. A toast says "Progress merged" and asks for a restart.
  The Firestore document keeps its old shape (`{data, updatedAt, v: 1}`), so the **rules are unchanged** (nothing to
  deploy) and older clients still read new copies. The meta travels inside `data`.
- **Recovery screen** (`src/ui/SaveRecoveryScreen.ts`), simple single sheet per Phase 8. It opens by itself before the
  menu when a store cannot be read (cut-short JSON, `undefined`, `[object Object]`, empty versioned key), and when
  `new Game()` throws (the "could not start" variant). It can also be opened from Settings → Advanced → Cloud save →
  **Backups and recovery** or with `?recover` in the URL. The sheet shows what is damaged (by friendly name), the
  backups with date, reason and progress (missions · XP · campaign mission), and the **Restore** button (tap twice).
  It also has **Repair** (resets only the damaged stores, kept in the undo slot), **Export profile**,
  **Import profile** and **Continue/Close**. While the game is running, any change reloads the page.
- **Settings → Cloud save** gains one row: `Profile: [Export file] [Import file] [Backups and recovery]`.
- **Arabic + FR/DE/ES** for all new strings: `src/i18n/{ar,fr,de,es}/saveSystem.ts`.

## Not done / notes
- The automatic merge only runs inside pushes (mission end, "Save now") and "Load profile". There is no background sync
  at boot, to keep Firebase off the start-up path.
- Merged stats show after a restart (the running game keeps its in-memory copies). The toast says so.
- Because growing stats are merged with max/union, a deliberate local reset of those stores on one device is undone by a
  newer cloud copy that still has them. Today the game has no "reset progress" option, so this does not happen in practice.
- Dates in the Arabic UI use Latin month names (`en-GB`), matching `fmtDate` elsewhere.
- I ran the shot script outside `tools/heavy.sh` because all three heavy slots were held by long voice jobs, and this is a
  light UI check.
