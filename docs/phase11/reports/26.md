# Phase 11 · 26 — Arabic voice-over: report

Branch `phase11/26-arabic-voice`. Local goal (Chatterbox multilingual on the Mac GPU/CPU, `.venv-tts`).

## Result
- **1,121 of 1,307 clips (86%) have an Arabic take** in `public/audio/voice/ar/` (19 MB, mono AAC 16 kHz,
  lazy-loaded clip by clip, only when the game language is Arabic). Every radio role has its Arabic voice.
- **Not done yet: the 61 briefing paragraphs, 49 `lead` clips and ~76 scattered radio clips** (37 of them
  rejected on the first seed and queued for a retry with other seeds). They fall back to the English
  recording per clip. The batch workers are still rendering them; follow-up commits add them (no code change
  needed, the runtime picks up whatever the Arabic manifest lists).
- Why it is slow: the Mac was shared with ~10 agents (load 15–50, GPU busy with Blender bakes) and slept
  overnight; a take that renders in ~3 s on an idle GPU took ~20 s, so the run averaged 46 s per clip.

## How it works
- **Text**: `tools/voice/arabic.mjs` translates every clip's English text with the game's own phrase tables
  (`tx()`), so the voice says exactly what the Arabic subtitle shows (runtime-filled crew-room templates are
  translated template-first and filled with translated values) → `tools/voice/lines_ar.json` (851 texts).
  `src/audio/arabicSpoken.ts` makes it speakable: digits → Arabic words, `Fw 190`/`Bf 109`/`P-51D`/bomber names
  transliterated, `.50` calibre, dashes/ellipses → pauses.
- **Voices**: same 17 per-role reference voices as the English casting (`tools/voice/refs/`), cross-lingual
  cloning with `ChatterboxMultilingualTTS(language_id='ar')`; `audio.ar.cfgScale = 0` in `lines.json`
  (no classifier-free guidance carries the least English accent over — A/B: 10 vs 8 of 22 clips clean).
- **Quality gate** (`generate.py --lang ar`): the multilingual model stays clear for one short phrase but tends
  to babble after the first sentence of a long line (A/B transcripts showed it), so each line is split into
  sentences / comma phrases (≤ 7 words, 1–2-word sentences ride with the next), each phrase is rendered up to
  3 times and **checked by Whisper large-v3-turbo** (local HF cache, mapped onto transformers in `.venv-tts`,
  nothing installed or downloaded): the first take with CER ≤ 0.25 and a plausible length is kept, else the
  best of 3. Phrases are joined with 0.12 s / 0.28 s pauses, then the usual trim, normalise, AAC.
- **Measured** (Whisper transcript vs. spoken text, normalised CER over 1,121 clips): median **0.086**,
  mean 0.101, 844 clips ≤ 0.15, 44 clips > 0.30 (mostly transliterated English names/nicknames that Whisper
  spells differently). This is an intelligibility proxy, not a native-speaker accent judgement; the voices keep
  a light foreign accent from the English references.
- **Batches**: `tools/voice/arabic_batches.sh [i/n]` renders 30 clips per `tools/heavy.sh` slot, role by role,
  resumable; passes 1–2 retry rejected clips with other seeds (`--reseed`). `--shard i/n` lets workers share a
  run (manifest/metrics merged under a lock); `TTS_DEVICE=cpu` runs a worker on the CPU while the GPU is busy.

## Runtime (small hooks)
- `src/audio/VoiceLang.ts` (new): loads `audio/voice/ar/manifest.json` once Arabic is active, maps a clip id to
  its Arabic file, falls back to English per clip, reloads on a language switch.
- `src/audio/Voice.ts`: fetches through `voiceUrl()`; on a language switch drops decoded buffers (generation
  counter discards in-flight decodes) and re-warms. Lookup stays on English ids/text, so clock composition
  ("مقاتلات،" + "الساعة التاسعة من الأسفل!") works unchanged.
- `src/audio/BriefingVoice.ts`, `src/ui/CrewRoomScene.ts`: same URL switch, cache keyed per language; crew-room
  lines without a recording use an Arabic system voice for the Arabic line when the device has one.
- No new player-visible strings (so no new phrase table was needed); comments in `src/i18n` updated.
