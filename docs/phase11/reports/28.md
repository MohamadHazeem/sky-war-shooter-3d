# Phase 11 · 28 — Dynamic in-mission events: report

Branch `phase11/28-mission-events`. A data-driven library of **22 short, readable gunner events**,
paced by a director that never lets them overlap with each other or with the existing set pieces,
random events or bonus-objective moments.

## The library (`src/game/MissionEventLib.ts`, pure data + rules)

Every event in the brief, plus twelve more. Each is 9–22 s long and made of timed beats: a radio
line (recorded clip + subtitle) and/or an action from a small vocabulary.

| Event | What happens |

| nearMiss | a B-17 slides in to 48 m off the gun window; the pilot jinks, the ship is rocked |

## Director (pacing) — `eventDue` / `eventFits` / `pickEvent`

- Gunner missions only; never in co-op, signature/tutorial missions or with `midRound: false`;
  never in a boss fight or the final wave; never in the first 30 s of a mission or within 15 s of a round edge.
- One at a time, 50–90 s apart, at most 6 a mission, never repeated in a mission. Weighted pick;
  a second B-17 loss in a row is less likely.
- 'calm' events need a quiet sky (≤2 fighters near, ≤4 in the breather); 'tense' ones ≤6; events that
  spawn fighters ≤4. 'loss' events share the set pieces' loss budget (`SP_MAX_LOSSES`, `World.scriptedLoss`),
  so they never count toward a mission's loss limit.
- **No overlap:** MidRound's objectives, random events and set pieces wait while an event runs and for
  8 s after (`events.busy`). Events wait for a random event (and 20 s after it starts), a set piece
  (and its quiet after), and the first/last 8 s of a bonus objective. A running objective may carry on:
  events never pick the ships it marks. While an event runs, low-priority crew chatter is held back
  (`World.holdRadio`); urgent combat calls still get through. The bomb-run hold stops a running event.
- Neighbour events stage a B-17 into the gun's view first (`SetPieces.stage`, ~4 s slide), so they
  happen where the player is looking. Everything an event changes is put back when it ends or is
  stopped: slots, the frozen gun, the jamming, scripted aircraft, pinned attackers.

## UI (Phase 8 simple UI)

The banner ("IN FLIGHT · NO SHOT · A crippled Bf 109 pulls alongside"; bailout keeps a live chute count)
shows only at HUD detail **Full**: Phase 8's clean-HUD rule hides optional panels on Standard and Minimal,
and there the radio subtitles and the visuals carry the event. Loss events also get a drama shot
(kill-cam rules). All new text is in Arabic (banner, 22 titles and lines, 62 radio lines, the JAMMED stamp).

## Visual verification (`tools/mission_events_check.mjs`, port 5428, Playwright bundled headless shell)

Shots in [`docs/phase11/shots/28/`](../shots/28/), results in [`results.json`](../shots/28/results.json):
one per event at its key moment (Standard HUD, 1280×720), plus `salute-full`/`bailout-full` (banner),
`salute-ar`/`jamming-ar` (Arabic, RTL), `bailout-phone` (844×390). The sweep: 27 event runs,
**0 page errors, 0 shader programs compiled during events, nothing left active, jammed or frozen**.
The pacing pass autoplays three full gunner campaign missions (Twelve O'Clock High, Black Thursday,
Last Light, ~400 s each): 2, 2 and 3 events started by the director, **no overlaps** with random
events or set pieces.

Reviewed the shots and fixed the weak ones: the bailing Fw 190 was shot down by the AI crew before the
pilot jumped (now held fire until he's out); chaff, brass, oxygen-fire smoke and the flare head were too
faint; the limping P-51 and the closing-up box were out of the gun's view; the near-miss ship came to
26 m (now 48 m, stepped up/down).
