# Phase 6 goal 04 — Co-op v2

Implemented on `phase6/04-coop-v2`. Nothing pushed or deployed.

## Changes and hooks

- `src/game/CoopSession.ts`: authoritative crew score and separate gunner ledgers; +5 per confirmed hit, kill points from both guns, named partner feed, synchronized field perks. Reliable versioned debrief, once-per-sortie rewards, ready handshake, reusable lobby, stale packet rejection, and AI takeover after disconnect. Guest shots/hits/kills come from the host, not local visual bullets.
- `src/net/CoopResult.ts`: pure score merge, personal reward split, medal selection and full debrief payload validation. Each gunner keeps their combat points; shared bonuses split equally. Failure halves the pool, rounding only once. Merit is paid at debrief; career XP uses the personal share and own kills.
- Shared hooks: `MissionFlow.ts:126` labels the crew HUD; `:160` defers co-op round merit to avoid double payment; `:235` delegates before solo debrief/leaderboard rewards. `GameHud.ts:83` displays crew kills. `ServiceRecord.ts:244` uses personal score for XP. `UI.ts:270` and its debrief show crew score and the lobby-return action. `Game.ts:390` routes pause-menu restarts through the host so both peers receive a fresh sortie epoch. No World.ts changes or new shader/material variants.
- `CoopScreen.ts`, `LeaderboardPanel.ts`, `Leaderboard.ts`: callsigns entered before connecting; only the host can submit the combined `Reed + Walsh` entry to `coop-gunner`. Full 20-character names survive submission; solo limits stay unchanged. Submission is disabled while pending and removed after success.
- `src/net/Ice.ts`, `Coop.ts`, `worker/index.ts`, `wrangler.jsonc`: fetch optional ICE credentials before signalling; 3-second client timeout and validated STUN fallback. Worker handles only `/api/turn`, mints 2-hour credentials server-side, enforces same-origin POST, times out upstream requests, and returns `Cache-Control: no-store`. Static assets keep their existing `_headers`; Worker responses set their own headers. No secrets are in the browser bundle or repository.
- All new runtime copy is translated in `src/i18n/ar/coop.ts`. No new radio lines.

## Owner TURN setup

1. In the Cloudflare dashboard, select the account that owns `sky-war-shooter-3d`, open **Calls / Realtime → TURN → TURN keys**, and create a TURN key (for example `sky-war-shooter-3d`). Copy its **Key ID** and generated **API token** into your password manager. These are the TURN key's credentials, not the account-global API key. [Cloudflare credential documentation](https://developers.cloudflare.com/realtime/turn/generate-credentials/).
2. From the repository, set the two Worker secrets interactively; paste each value only into Wrangler's prompt:

   ```sh
   npx wrangler secret put TURN_KEY_ID --name sky-war-shooter-3d
   npx wrangler secret put TURN_KEY_API_TOKEN --name sky-war-shooter-3d
   ```

3. When ready, the owner builds and deploys the reviewed Worker plus static assets through the normal release process. The new `main` and `assets.run_worker_first: ["/api/turn"]` configuration routes only the credential endpoint through the Worker. [Cloudflare asset routing](https://developers.cloudflare.com/workers/static-assets/routing/worker-script/).
4. On the deployed game, host/join should make a same-origin `POST /api/turn` returning temporary `iceServers` and `Cache-Control: no-store`. Test with players on different networks; inspect the selected ICE candidate pair in browser WebRTC diagnostics to confirm `relay` where needed. Missing secrets or a failed route automatically use STUN. Credentials expire after two hours; start a new connection for a longer session.
