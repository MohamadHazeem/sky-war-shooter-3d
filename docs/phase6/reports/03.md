# Phase 6 goal 3 — cloud-top shimmer

Implemented in `src/render/Clouds.ts` only; no Game/World/UI hooks. All four presets retain their original step counts, march extent, weather coverage, haze and temporal resolve.

- Lines 99–141: density and sun-light samples use explicit noise mip levels. Below/inside a layer and the shadow map use level zero, preserving the original sampling.
- Lines 172–180: above a layer, the march-step footprint selects the shape/detail mip levels. Filtering fades in over the first 100 m above the top. As detail becomes filtered over 2–8 texels, jitter fades toward the cell centre (including light-march jitter). This removes stochastic offsets that still flickered after history clamping.
- Lines 557–563: generate noise mip chains once at startup. No additional material, shader variant, runtime recompile or per-frame JS allocation.

The result is softer, steadier distant cloud tops with the existing cloud sea and horizon intact. Fine structure below the sampling footprint is intentionally softened; this is an approximation of filtered density, not a new physical cloud model. Low also loses spatial stipple despite having no temporal accumulation. Residual variation remains on temporal tiers.

## Cost

High remains 56 steps; no extra march/light iterations or texture instructions. Added work is two logarithms and a few scalar operations **per intersected ray**, outside the loops. Fractional mip sampling can fetch two levels, but the filtered levels are smaller and more cache-friendly. The mip chains add about **151 KiB** of texture storage and one-time generation/upload work. Level-zero views retain the original noise.

An alternating-order, GPU-synchronized full-render benchmark (12 batches, 144 measured frames per renderer/view, High, clear weather, 1280×720) showed no regression on this machine: median **3.5 → 3.0 ms** at 6000 m and **3.8 → 3.6 ms** at 7600 m. Means were 6.06 → 5.18 ms and 6.07 → 5.19 ms; timings include scheduling noise and are not a cross-device guarantee. [Raw timings](../shots/03/bench.json).

## Reproduce in the dev console

Start `npx vite --port 5252 --strictPort`, open `http://localhost:5252`, wait for `sws.vqa`, then run this on the baseline or changed revision:

```js
const Vector3 = sws.engine.camera.position.constructor;
const { Atmos } = await import('/src/render/Atmosphere.ts');
const { engine: e, vqa: v } = sws;
v.freeze(); v.mood('clear'); v.quality('high');
e.time = 0; Atmos.windOffset.set(0, 0, 0);
e.renderScale = 1; e.resize();
e.renderer.setPixelRatio(1); e.renderer.setSize(1280, 720, false);
for (const rt of [e.sceneRT, e.hdrRT]) rt.setSize(1280, 720);
e.clouds.setSize(1280, 720); e.post.setSize(1280, 720);
e.heatHaze.setSize(1280, 720); e.camera.aspect = 1280 / 720;
e.clouds.resetHistory(); e.clouds.frameN = 0;
v.look(new Vector3(0, 6000, 0), new Vector3(0, 5500, -10000), 50, 64);
v.scan(); // no bad HDR pixels expected
sws.shot(); // data URL; screenshot captures used one further render
```

For Low/Medium/Ultra, replace `'high'` and rerun the setup. For inside/below regression views, replace the camera/target heights with `(5000,4500)` / `(3000,3500)`. To reproduce the moving view after the initial setup, advance 120 renders with `e.camera.position.z -= 1.5; e.camera.updateMatrixWorld(); e.time = frame / 60; e.render(1 / 60)` for `frame = 0..119`. Inspect the cloud tops and the full horizon, then `v.scan()`.
