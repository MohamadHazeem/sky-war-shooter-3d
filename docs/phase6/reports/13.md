# Phase 6 · 13 — Natural crew voices

Implemented and sampled on `phase6/13-chatterbox-voices`. **51 Chatterbox clips, three per role**, including seven clock calls and three briefing paragraphs, are in the real `public/audio/voice/`. The remaining 1,117 clips retain their original recordings. No push/deploy or dependency installation.

## Changes and hooks

- `tools/voice/generate.py`: engine dispatch/bootstrap (`ensure_tts_python`, line 178), emotion expansion (44), reference-content hashes (99), sequential MPS render/resample/retry/encode (223), atomic manifests and partial selection (277, 285, 395). Existing runtime manifest schema and AAC pipeline retained; legacy say hashes remain valid. Progress/ETA every 25 clips, checkpoints every 50 and on exit/interruption. Failed takes preserve the old clip/hash and return nonzero after four attempts.
- `tools/voice/lines.json`: Chatterbox engine, 17 role references, existing voice/rate fallback fields retained. Blue Three originally had only **two** clips; added its take of the existing translated `kill_going_down` line before the briefings group, making 1,168 clips total. This is the only generated `src/audio/voiceLines.ts` change (speaker list, line 60). No new English/Arabic text or gameplay hooks.
- `tools/voice/build_refs.py`, `refs/*.flac`, `refs/sources.json`, `refs/README.md`: reproducible per-utterance VCTK downloads, source row IDs/transcripts, casting and attribution. 17 unique male speakers, 3–5 complete utterances each, mono 24 kHz / 16-bit FLAC, 10–12 seconds, 120 ms gaps. About 4.5 MB total references.
- `tools/voice/sample.py`: repeatable exact 51-clip sample using `--only` and `--limit`; identical repeat runs select the same set and skip valid hashes. `tools/voice/browser_check.mjs`: real-browser decode/playback verification. Pipeline usage and credits updated in `tools/voice/README.md` and `public/audio/CREDITS.md`.
- `tools/voice/test_generate.py` and `tests/voicePipeline.test.ts`: eight offline Python tests, integrated into `npm run check`; cast/FLAC validation, engine/reference/emotion hash isolation, legacy say hash compatibility, partial force/resume, unknown selector, retry seeds, four-take rejection, preservation of previous clips, silence/duration metrics, and coverage-check regression protection.

## Quality without listening

144.640 s of generated speech; 491.42 s total per-clip render time (model startup excluded), median 6.76 s/clip, 3.40 render seconds per speech second. Duration-weighted extrapolation for the remaining 3575 s of legacy speech is **about 3.4 hours**, plus startup/retries; this is an estimate, not a benchmark of the full run.

Retries: 0 total; exhausted failures: 0. Duration gates use `words / 2.95` expected seconds, accepting 0.35–2.2×. They detect gross truncation/runaway output, not mispronunciations or hallucinations. Per-clip peaks/RMS below are from normalised PCM **before AAC**; silence is the proportion of 20 ms windows below −40 dBFS. [Machine-readable measurements](13-samples.json) also include **float-decoded final AAC** metrics, spoken-text substitutions, seeds and hashes. AAC peaks range -1.72 to 0.32 dBFS. AAC reconstruction can overshoot the −1 dBFS PCM peak; float decoding preserves that headroom for measurement.
