## Interaction check: living formation (goal 1) × bomb run (goal 2)

- **No double-counted losses.** The sweep counts every `bomberLost` event per B-17. In all 72 runs: 0 B-17s reported twice.
  Every `bombersLost` matches the events, plus one when the player's own ship ditches (that path counts without an event,
  on purpose). Every loss path is guarded by `alive`, and nothing revives a bomber.
- **Stragglers vs straight-and-level:** AI stragglers keep falling back during the bomb run's level hold (realistic). The
  hold only freezes the player's jinks and roll, and the rally afterwards doesn't touch straggler slots.
- **Ditching on the return leg vs bomb-run rally:** the real problems were 5 and 6 above (ditches firing mid-mission and
  ending it, and a staged ditch able to fail the mission). Both are fixed. The companion ditch still needs bombs dropped and no battle group.

## Harness (new, dev only)

- `src/dev/qaSweep.ts` (`sws.qa(job)`): autoplay with QA sampling. Hooks: `AutoplayOpts.onStep` (`autoplay.ts:28`),
  `runJob(..., onStep)` (`balance.ts`), and the `sws.qa` registration in `main.ts`. Balance jobs accept chapter ids (`dp1`–`dp5`).
- `tools/qa_sweep.mjs <campaign|difficulty|survival|highar|ace|smoke> [out.jsonl]`, `--report`. One warm browser context;
  each job wipes the saved state and reloads. Documented in `docs/TESTING.md`.
- `tools/qa_voice_overlap.mjs [missionIndex] [seconds]`: real-time voice overlap check from the briefing into the mission.
- Both use an existing Playwright install (`PLAYWRIGHT_MODULE`) and the installed Google Chrome (`QA_CHROME`). The shared
  npx Playwright was swapped to an alpha that needs an uninstalled browser during this task; the 1.63 install still works.
